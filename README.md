# SignCourse Studio · 手语课程编排工具

SignCourse Studio 是面向手语教师的课程设计工作台。课程拆为**共享课程库**与**老师个人课程**两边：教研组长在库里维护标准课程并发布版本；老师从库里取一份到自己名下编排学习步骤，改好的步骤可申请回灌到库里。

## 角色与分工

- **教研组长（陈组长）**：维护共享课程库的标准课程与学习步骤，维护工作稿并"发布新版本"；审核老师回灌的步骤，可单项确认或退回。
- **任课老师（林老师 / 王老师）**：从课程库取一份标准课程到个人名下，自由编排学习步骤；个人自建内容不跟随课程库；改好的标准步骤可勾选后申请回灌。

右上角可随时切换身份体验两条工作流，顶部连接按钮可模拟**课程库中断 / 恢复**。

## 核心规则

### 取用与越权拦截

- 老师在课程库里是只读：所有标准步骤字段锁定，任何写操作都会被"越权操作已拦截"挡下，库里内容不发生变化。
- 老师点"取用到我的课程"得到一份独立副本，同一门课不允许重复取用。
- 个人副本的步骤带跟踪状态：
  - `未改动 (clean)`：取用后没动过；
  - `已自改 (dirty)`：老师改过，库升级不会覆盖它；
  - `个人自建 (local)`：老师自己新建、库里没有的步骤；
  - `已定夺 (resolved)`：版本冲突后由老师裁定过。

### 发布升级与两版冲突

教研组长发布课程库新版本后，所有取用过该课的老师副本自动对版本：

- **没动过的步骤**：内容静默升级到新版本；
- **动过且与新版不同的步骤**：内容原样保留、绝不被悄悄替换，进入"版本冲突"页，把"我的版本"和"课程库新版本"两版逐字段摆出来，由老师点"保留我的版本 / 采用库新版本"定夺；
- 冲突未决时老师直接继续编辑，等同于选择"保留我的版本"，且新输入内容不会被旧快照覆盖；
- 老师的自改若恰好已通过回灌被库采纳，升级时静默对齐、不再打扰。

### 回灌与断线保留

- 老师在个人课程勾选改好的标准步骤（个人自建步骤不回灌）发起申请，申请按**学习步骤逐项**补入课程库工作稿，等组长审核后随下次发布生效。
- 课程库中断时发起回灌不会丢：申请以"待补入"状态留在本地，老师仍可继续编辑；恢复连接后系统自动（或在"我的回灌申请"页手动）逐项补上。
- 单项失败不影响其他步骤：失败项记录原因、保留可重试；组长也可以只退回某一个步骤，库工作稿的该步骤会还原为补入前内容。

### 旧数据归属迁移

首次进入新版本时，旧的单人本地稿（`sologsb-1012-sign-course-project-v1`）自动迁移：

- 整门课按稿子里的任课老师归属迁到其个人课程名下（演示稿归林老师）；
- 与课程库已发布步骤逐字段一致的步骤挂接为标准步骤（`未改动`、携带库版本号，之后可跟随升级）；
- 老师在旧稿里调过的步骤保留为`个人自建`；
- 迁移完成后旧稿归档，迁移结果在"我的课程"页有说明条。

## 原有编排能力

- 课程模块与学习步骤：示范 / 讲解 / 练习类型、时长、入门 / 进阶 / 挑战难度。
- 动作素材：示范片段名称、本地素材地址、手形说明、动作区域、镜头角度。
- 字幕与无障碍：字幕文本、字幕位置、替代文本，预览中标记字幕与动作区冲突。
- 学习依赖：前置步骤选择与"步骤跳级 / 前置不存在"检查。
- 练习设计：练习任务、反馈方式、常见错误清单。
- 设备预览：手机 9:16 / 平板 4:3 切换，带检查点的动作时间线。
- 发布前检查：字幕遮挡、步骤跳级、替代文本缺失、练习反馈不完整、常见错误缺失。
- 离线：所有数据在 `localStorage`（工作区键 `sologsb-1012-sign-course-workspace-v2`），可撤销 / 重做（`⌘/Ctrl+Z`、`⇧⌘/Ctrl+Z`），`Alt + ↑/↓` 调整步骤顺序。

## 数据模型（src/models.ts）

- `LibraryCourse / LibraryModule / LibraryStep`：课程库工作稿，步骤带 `version`，发布产生 `CourseVersion`。
- `PersonalCourse / PersonalModule / PersonalStep`：老师名下副本，步骤带 `state` 与 `originVersion`；`StepConflict` 保存两版快照与老师裁定。
- `BackfillRequest / BackfillItem`：回灌申请与逐项条目（`pending / applied / rejected / failed`、失败原因、重试次数、补入前快照）。
- `Workspace`：身份、课程库、个人课程、申请、库连接状态、迁移记录。

## 开发

```bash
npm install
npm run dev      # 开发服务器（默认 3333）
npm test         # 单元与组件测试（Jest + Stencil spec）
npm run build    # 生产构建输出到 www/
```

业务逻辑测试见 `src/spec/store.spec.ts`（迁移、越权拦截、发布升级 / 冲突、回灌断线重试、退回还原），组件冒烟测试见 `src/components/app-root/app-root.spec.tsx`。
